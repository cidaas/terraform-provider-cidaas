# cidaas_notification_service_setup (Resource)

Manages a **communication provider service setup** via **notification-srv** (`POST/PATCH/DELETE /{notifications_context_path}/servicesetups`).

**`status`** is computed from `GET` and reflects manual verification in service-desk (e.g. `in-progress` → `active`). Terraform does **not** call verify.

Provider credentials are configured in service-desk after create. Destroy treats remote **404** as success. Active setups must be deactivated outside Terraform before delete.

**Scopes:** `cidaas:service_setups_read`, `cidaas:service_setups_write`, `cidaas:service_setups_delete`.

## Example Usage

```terraform
resource "cidaas_notification_service_setup" "twilio_sms" {
  name                  = "Twilio SMS"
  service_id            = "twilio-sms"
  communication_methods = ["sms"]
  description           = "Twilio SMS communication provider setup"
}
```

## Schema

### Required

- `communication_methods` (Set of String) Communication methods for this setup (lowercase: `email`, `sms`, `ivr`, `push`). Stored in `serviceDescInfo.commProv.commMethods`.
- `name` (String) Human-readable name.
- `service_id` (String) Service id (`serviceDescInfo.serviceId`). Immutable after create.

### Optional

- `description` (String) Optional description.
- `has_remote_templates` (Boolean) Whether templates are remote.
- `parent_service_setup_id` (String) Parent service setup id. Optional in config; if omitted, the platform may auto-populate it on create.
- `service_category` (String) Service category (`serviceDescInfo.serviceCategory`). Default: `comm_prov`.

### Read-Only

- `id` (String) Service setup `_id` from notification-srv.
- `status` (String) Setup status from the API (`in-progress`, `active`, `inactive`). Updated on read/plan refresh after manual verify.
