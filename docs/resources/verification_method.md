# cidaas_verification_method (Resource)

Manages an MFA verification method on cidaas v4 via `verification-actions-srv/config` (Admin → Multifactor Settings → MFA Settings). Separate from `cidaas_verification_options` and `cidaas_suggest_verification_method`.

**System methods** (`EMAIL`, `SMS`, `TOTP`, …, owner other than `CLIENT`) already exist: Terraform adopts them and manages `active`, `locale_text` and `encryption_config`. Destroying the resource only removes it from state; the method is left unchanged.

**Pluggable methods** (owner `CLIENT`) are created and deleted by Terraform and need `url`, `auth_type` and `cidaas_auth_details`.

Whether a method is system or pluggable is decided by its `owner` on the server, like verification-actions-srv does.

## Example Usage

```terraform
# System method (EMAIL, SMS, TOTP, ...): it already exists on the tenant. Terraform adopts it and manages
# active, locale_text and encryption_config. Destroying the resource only removes it from state.
resource "cidaas_verification_method" "email" {
  verification_type = "EMAIL"
  active            = true

  # Optional. The API replaces the whole list; when omitted, the current texts are kept.
  locale_text = [
    { locale = "en", name = "Email", description = "Verify with a code sent by email" },
    { locale = "de", name = "E-Mail", description = "Bestätigung mit einem Code per E-Mail" },
  ]
}

# Disable a system method.
resource "cidaas_verification_method" "pattern" {
  verification_type = "PATTERN"
  active            = false
}

# System method with an existing encryption configuration on the tenant: only enabled and mode can change.
resource "cidaas_verification_method" "sms" {
  verification_type = "SMS"

  encryption_config = {
    enabled = true
    mode    = "REQUIRED"
  }
}

# Pluggable method (owner CLIENT): created and deleted by Terraform.
resource "cidaas_verification_method" "custom_otp" {
  verification_type = "CUSTOM_OTP"
  active            = true

  url       = "https://mfa.example.com/verify"
  auth_type = "Bearer"
  cidaas_auth_details = {
    client_id = "11111111-2222-3333-4444-555555555555"
  }

  factor     = "POSSESSION"
  category   = "code"
  icon       = "https://cdn.example.com/custom-otp.svg"
  amr_values = ["custom_otp"]

  locale_text = [
    { locale = "en", name = "Custom OTP", description = "One-time code from the custom MFA service" },
  ]
}
```

## Schema

### Required

- `verification_type` (String) Verification method type: a system type (`PASSWORD`, `EMAIL`, `SMS`, `IVR`, `TOTP`, `PUSH`, `TOUCHID`, `BACKUPCODE`, `FACE`, `FIDO2`, `PATTERN`, `CHAT`) or the name of a pluggable method. Changing it forces a new resource.

### Optional

- `acr_pin` (String) ACR value. Writable for pluggable methods only.
- `active` (Boolean) Whether the method is enabled. Kept as is when omitted.
- `amr_values` (List of String) AMR values. Writable for pluggable methods only; values already used by system methods are rejected by the API.
- `auth_type` (String) Pluggable only. How cidaas authenticates against `url`: `Bearer`, `oauth` or `oauth2`. Required with `url`.
- `category` (String) Method category, e.g. `code`, `biometric`, `hardware`. Writable for pluggable methods only.
- `cidaas_auth_details` (Attributes) Pluggable only. cidaas client used to obtain a token for calling `url`. Required with `url`. (see [below for nested schema](#nestedatt--cidaas_auth_details))
- `encryption_config` (Attributes) Encryption settings. System methods only, and only when the method already has an encryption configuration on the tenant. Only `enabled` and `mode` can be changed. (see [below for nested schema](#nestedatt--encryption_config))
- `factor` (String) Authentication factor: `KNOWLEDGE`, `POSSESSION`, `INHERENCE` or `DELEGATION`. Writable for pluggable methods only.
- `icon` (String) Icon. Writable for pluggable methods only.
- `locale_text` (List of Object) Display name and description per locale, as a list of `{ locale, name, description }` objects (all three keys are required; use `""` for an unused name or description). The API replaces the whole list on every update, so when omitted the current texts are sent back unchanged. (see [below for nested schema](#nestedatt--locale_text))
- `prerequisite` (String) Pluggable only. Prerequisite of the method.
- `url` (String) Pluggable only. Absolute URL of the pluggable method's service (scheme and host).

### Read-Only

- `algorithm_type_id` (String) Password algorithm (PASSWORD method).
- `code` (Attributes) Code settings of code-based methods (read-only). (see [below for nested schema](#nestedatt--code))
- `created_time` (String) Creation timestamp.
- `description` (String) Description resolved by the API from `locale_text`.
- `id` (String) Same as `verification_type`.
- `name` (String) Display name resolved by the API from `locale_text`.
- `owner` (String) `CLIENT` for pluggable methods; any other value (e.g. `system`) for system methods.
- `requires_authenticator_app` (Boolean) Whether the method needs the authenticator app.
- `updated_time` (String) Last update timestamp.

## Import

Import is supported using the following syntax:

```shell
# In the import statement, the identifier is the verification_type of the method.
# System methods (e.g. EMAIL) and pluggable methods (e.g. CUSTOM_OTP) are imported the same way.
# For example:

terraform import cidaas_verification_method.email EMAIL
```

Both system methods (e.g. `EMAIL`) and pluggable methods are imported by `verification_type`. After importing a system method, `terraform destroy` only removes it from state; the method stays on the tenant.
