# cidaas_event_retention (Resource)

Manages per-event-type data retention (`daysToLive` of changelog and user activity events) on cidaas v4 via `webhook-srv/eventdescriptions/retention`. One instance per tenant. Separate from `cidaas_webhook`.

Requires the event retention feature (`custom_reporting`) to be active on the tenant and the scopes `cidaas:eventdescriptions_retention_read` and `cidaas:eventdescriptions_retention_write` (`cidaas:webhook_read` is optional and only used to tell unknown event types from immutable ones in errors).

Only the event types listed in `retention` are managed. Removing an entry, or destroying the resource, restores that event type to its default `daysToLive`.

## Example Usage

```terraform
# Example: cidaas_event_retention Resource (v4 Trustdesk)
#
# Sets how many days changelog / user activity events are kept, per event type.
# Requires the event retention feature (custom_reporting) on the tenant.
# Only listed event types are managed; removing one (or destroying the resource)
# restores its default daysToLive. See the computed `catalog` for configurable
# event types and their min/max bounds.

resource "cidaas_event_retention" "sample" {
  retention = {
    ACCOUNT_MODIFIED = 1000 # bounds 365..1095, default 730
    ACCOUNT_DELETED  = 45   # bounds 7..60, default 30
  }
}

output "event_retention_catalog" {
  value = cidaas_event_retention.sample.catalog
}
```

### Required

- `retention` (Map of Number) Map of event type ID (e.g. `ACCOUNT_MODIFIED`) to `days_to_live`. Each event type must be configurable (listed in `catalog`) and each value must be within its `min_days_to_live` / `max_days_to_live`.

### Read-Only

- `catalog` (Map of Object) All configurable event types on the tenant, keyed by event type ID, with `object_type`, current `days_to_live` and the `default_days_to_live` / `min_days_to_live` / `max_days_to_live` bounds. (see [below for nested schema](#nestedatt--catalog))
